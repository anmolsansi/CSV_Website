# JobGrid Cloud Deployment: Vercel + Render + Supabase

This runbook deploys JobGrid with a zero-cost-first architecture:

- **Vercel**: React/Vite frontend
- **Render**: FastAPI backend
- **Supabase**: managed PostgreSQL only

Supabase Auth, Storage, Realtime, and the Data API are not required for this deployment. The FastAPI backend remains the only application layer that reads and writes PostgreSQL through SQLAlchemy.

## Repository deployment assets

- `/render.yaml` — Render Blueprint for the backend
- `/backend/.python-version` — pins the Render Python runtime to the same 3.12 family used by the backend Docker image
- `/frontend/vercel.json` — SPA fallback for React Router/deep links

## Deployment order

1. Create/import the Vercel project with `frontend` as the project root.
2. Create the Supabase project.
3. Create the Render backend from this repository.
4. Add the Supabase connection string and frontend URLs to Render.
5. Verify `GET /health` on Render.
6. Point the frontend API traffic at Render (initially with `VITE_API_URL`, or later through a Vercel `/api/*` reverse proxy).
7. Configure OAuth callback URLs.
8. Run end-to-end verification.

## Supabase

Use Supabase as PostgreSQL only.

Recommended project settings:

- Project name: `jobgrid`
- Region: `ap-southeast-1` (Singapore), to stay close to the Render Singapore service
- Plan: Free

For Render, use the Supabase **Session Pooler** connection string if a direct database hostname is not reachable over IPv4.

Set the complete connection string in Render as `DATABASE_URL`. Never commit it to this repository.

The application starts Alembic automatically whenever `DATABASE_URL` is not SQLite, so the existing schema migrations are applied at backend startup.

## Render

The checked-in Blueprint creates a free Python web service named `jobgrid-api` in Singapore.

Required secret/runtime values requested during initial Blueprint setup:

- `DATABASE_URL` — Supabase PostgreSQL connection string
- `FRONTEND_URL` — Vercel production origin, for example `https://jobgrid.example.vercel.app`
- `CORS_ORIGINS` — initially the same Vercel production origin
- `OAUTH_REDIRECT_BASE` — backend callback base while using a direct Render API origin, or the Vercel `/api` base once the reverse proxy is enabled
- `GOOGLE_CLIENT_ID` — optional until Google OAuth is configured
- `GOOGLE_CLIENT_SECRET` — optional until Google OAuth is configured

`SECRET_KEY` is generated by Render from `render.yaml` and should not be copied into source control.

Render configuration from the Blueprint:

- Runtime: Python
- Python family: 3.12
- Region: Singapore
- Plan: Free
- Root directory: `backend`
- Build: `pip install -r requirements.txt`
- Start: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
- Health check: `/health`
- Auto-deploy: only after repository checks pass

Expected health response:

```json
{"status":"ok"}
```

## Vercel

Configure the Vercel project with:

- Root directory: `frontend`
- Framework: Vite
- Build command: `npm run build`
- Output directory: `dist`

`frontend/vercel.json` provides the SPA fallback required for React Router pages to load correctly when opened or refreshed directly.

Before the Vercel-to-Render reverse proxy is configured, set `VITE_API_URL` in Vercel to the public Render origin, for example:

```text
https://jobgrid-api.onrender.com
```

After `/api/*` is proxied through Vercel, change `VITE_API_URL` to:

```text
/api
```

and configure the backend's production frontend/CORS/OAuth values to match the final public origin.

## OAuth

For Google OAuth, keep client credentials only in Render environment variables.

When a Vercel `/api` reverse proxy is enabled, the Google callback should be:

```text
https://<VERCEL_HOST>/api/auth/callback/google
```

Until then, a direct Render callback can be used if the backend is exposed directly.

## Security rules

- Never commit `DATABASE_URL`, database passwords, OAuth secrets, or private keys.
- Keep `TEST_AUTH=false` in production.
- Do not expose Supabase service-role/secret keys to the frontend.
- This deployment does not need Supabase browser/database API access; PostgreSQL is accessed server-side by FastAPI.
- Keep a portable JobGrid backup outside Supabase because free-tier database backup guarantees are limited.

## Rollback

The deployment additions are configuration-only. Removing `render.yaml`, `backend/.python-version`, and `frontend/vercel.json` returns the repository to its previous deployment-neutral state. No application database schema change is introduced by this deployment preparation.
